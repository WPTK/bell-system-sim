You are helping to build a historically accurate simulation of a UNIX workstation used by internal AT&T employees in the late 1970s to early 1980s, prior to the Bell System breakup in 1984.

This simulation is intended to immerse the user in the experience of working as a technical operations employee in a realistic Bell System UNIX environment. It is not customer-facing; the simulated employee interacts only with other AT&T divisions and personnel. The goal is to authentically recreate the atmosphere, tools, and job functions of a UNIX-based role inside the Bell System, using technology and workflows from that era.

You are to generate code, scenarios, data structures, command-line interactions, and event logic that replicate the following conditions:

⸻

ENVIRONMENTAL REQUIREMENTS
	•	Operating System: UNIX Version 6 or 7 (V6/V7)
	•	Hardware Style: PDP-11 or similar AT&T UNIX machine from the era
	•	Terminal Display: Text-only, monochrome interface resembling ADM-3A or VT100 behavior
	•	No GUI, no Internet, no mouse
	•	All tools must reflect late-70s to early-80s capabilities only

⸻

TERMINAL & COMMAND BEHAVIOR
	•	Shell should simulate sh, not bash or modern shells
	•	Commands should behave like V6/V7 tools: ed, mail, uucp, cat, grep, awk, ps, kill, who, wall, cron, init, ls, df, du
	•	Terminal startup should begin with realistic login prompt (e.g. login:), motd (/etc/motd), load average, etc.
	•	Mail system must simulate BellMail, UUCP, and internal message memos with accurate formatting and delays

⸻

SIMULATED USER ROLES (SELECTABLE)

Each role has different permissions, task types, and access to tools:
	1.	UNIX Systems Operator (Regional Office)
	•	Maintains system uptime
	•	Monitors daemons and services
	•	Handles mail routing via uucp
	•	Analyzes logs and resolves process hangs
	2.	Switching Station Technician (1A/5ESS Central Office)
	•	Receives switching alarms and system codes
	•	Runs line tests, diagnoses trunk routing issues
	•	Interacts with remote switching equipment
	3.	Field Support Liaison
	•	Triages internal tickets from NOC
	•	Assigns tickets to field techs, logs completion
	•	Simulates coordination with techs using wall, write, and memo files
	4.	National NOC Analyst
	•	Oversees multi-state signal integrity
	•	Responds to large events like weather outages or power surges
	•	Sends alerts to field offices and regional systems

⸻

SIMULATED WORK EXPERIENCE
	•	Sessions simulate a “shift” (4–8 hours compressed to real-time or playable events)
	•	Users receive:
	•	Shift handoff memos (e.g., emails like "From: nocsysop!sysmail@bellcore")
	•	Alerts or events related to their role (switching failure, system load spike, power outage)
	•	Messages via TTY or simulated Teletype (write, wall, or cat /var/msg/tty3)
	•	Use authentic formatting and tone, e.g.:

SVC-07: Route Failure Detected  
Timestamp: 04:12 EDT  
SW-Center: RIDGE-X1  
Retry Attempts: 12  
Tech: Awaiting field assignment

SIMULATION DESIGN GOALS
	•	Build tools to simulate these systems
	•	Recreate Bell System’s pseudo-network feel using:
	•	Simulated uucp network for inter-office mail and job transfer
	•	Pseudo /etc/passwd, /etc/motd, /usr/spool/mail, etc.
	•	Files and folders for reports, logs, test outputs, internal memos
	•	Create a realistic randomness engine to inject plausible daily events:
	•	Small: line failure, daemon crash, bad login script
	•	Medium: field dispatch delay, regional switch downtime
	•	Large: weather-related outages, partial relay collapse

⸻

DESIGN CONSTRAINTS
	•	Do not use modern tech references, events, or commands (no sudo, no modern networking)
	•	Avoid any historical events (keep it as a “timeless” 1978–1983 world)
	•	No customer interaction—only internal Bell System operations
	•	All remote interactions must simulate TTY/modem-based control and line testing
	•	Simulate bureaucracy: memos, tickets, handoff logs, approvals

⸻

GOAL OUTPUTS

You should generate:
	•	Authentic UNIX terminal responses, including errors and diagnostics
	•	Email/message content, formatted in Bell System internal style
	•	Files and file contents (e.g. /usr/local/bin/test_line.sh, /usr/memos/shift_82_0403)
	•	Trouble ticket formats and log files
	•	Random system messages or alerts, with plausible content
	•	A realistic interface (text-only) that outputs events and allows user decisions using typed input
